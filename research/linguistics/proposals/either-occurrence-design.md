# Either occurrence transport without changing truth conditions

Design checkpoint82efe8d, building on reviewed proposal50197eb. Own prototype only; no production implementation, gold mutation or corpus observation. The lexical pairing guard remains a separate prerequisite. An occurrence transport API does not authorize either as free identity, XOR, sentence-initial S/S, N/N reanalysis, or neither/not-both.

## Concrete minimal representation

Keep `Term` unchanged. Add a private semantic payload `Marked { term :: Term, orOrigins :: Map TermPath OrOrigin }`. A path is a sequence of child indices in that exact term: binder/NOT body=0; binary/app left=0,right=1. It is NOT a source identity and must be rewritten with the term. Identity lives in immutable `OrOrigin { source, orSpan, pairedEither :: Maybe Span, operandSpans, originalCategory, semanticType, pairingLicense }`. Constructor private; direct typed OR coordination is the only initial minting site. A bare unpaired OR has `pairedEither=Nothing`, not an inferred identity marker.

The source/cat/operand evidence comes from the actual selected `CoordMark`/`CoordApply` transition, not formula matching, sentence text search or a replay guess. Paired certificates require50197eb's pending-marker guard, same source, actual offered category, disjoint ordered spans, explicit same-category OR edge and one unmatched marker. `pairingLicense` is a typed internal sum (ordinary explicit OR versus guarded correlative pair), not a documentary gloss. The path must point to TOr whose operands typecheck as t in the enclosing context. Subject continuation, lambda binders and variables retain their existing types. No new predicate is introduced.

For a VP coordinator the new OR is inside the lambda body; its path is created at that known constructor site, not recovered by finding an equal formula afterwards. Existing operand maps are prefixed when terms are built. Immutable evidence travels with those subtrees. All operator-producing helpers touched by a marked route must either transport/mint evidence correctly or abstain; no catch-all descendant search is permitted.

## Rewrite algebra and bounded rejection policy

1. **Constructor application:** prefix each child's map by its child index. Root OR annotation is a separate entry at empty path. Assert maps do not collide; every entry points to an OR. Ordinary predicates never carry an OR certificate.
2. **Capture-avoiding substitution:** recurse over the same constructors as Lambda.subst. At a replaced variable leaf, splice both the argument term and its entire relative map. At an unrelated node preserve its root certificate and recursively rebuilt children. Under a binder of the substituted variable stop. If a binder would capture a free argument variable, alpha-rename the binder/body exactly as current subst; alpha-renaming changes no constructor paths.
3. **Beta reduction:** normalize function and argument, substitute annotated argument into the lambda body, then normalize the result. For this first bounded candidate, if the argument has any certificates and its bound variable occurs freely zero or more than once in the body, reject with `unsupported-or-origin-beta-use`. This explicitly defers erased or duplicated source occurrences instead of inventing copy identities. Check the use count after normalizing the function body and with binder shadowing respected. No annotation-bearing argument is silently discarded.
4. **Logical constructors:** recurse through TOr/TImp/TNot/TAnd/TEq and existential/universal binders. Prefixes distinguish an antecedent from a consequent and one disjunct from another. A parent OR receives only its own edge certificate; it does not inherit inner markers. An enclosing NOT does not change OR to XOR or add exclusion. Predicate-level beta application may instantiate the same semantic individual in both OR operands; this duplicates an unmarked entity, not the OR origin.
5. **Conjunction simplification:** current chart `finish=simplifyConj.normalize` may flatten and alpha-deduplicate terms. Initial annotated route computes beta-normal form n and accepts simplification only when `simplifyConj n == n` structurally. Otherwise reject `unsupported-or-origin-conjunction-rewrite`. This conservative rule avoids a second rewrite engine and prevents equal propositions with distinct evidence being collapsed. Unannotated routes retain existing simplification. Even a truth-preserving change is not enough to prove annotation preservation.
6. **Typing:** typecheck the input and output in the same context and require identical type. Invalid paths, missing trusted origins, unsupported operations or inconsistent state produce explicit incomplete/abstaining candidates. Never strip the map and continue as a precise correlative reading.

This algebra supports the ordinary VP pair through copula/subject application and independent nested clause combinations without implementing a parallel full logical calculus. It deliberately does not claim complete lambda sharing, intensional transformations, AC annotation sorting, or list-rebuild transport. Its erasure on accepted cases equals ordinary beta normalization; rejected cases are coverage losses, not changed meanings. Every ordinary existing candidate with no marker obligation must retain its old semantics and policy.

## Packing, selected readings and lowering

Current chart packing uses canonicalAC(term); root `byMeaning` separately deduplicates on canonicalAC(term). Both are relevant. For annotation-bearing candidates use `(canonical term, exact relative origin map, other existing state)` in **both** places, not canonicalAC without a transported permutation. Alpha-canonicalization renames binders without changing paths. This conservatively distinguishes extra conjunction order rather than risk merging evidence. Keep all fused/conditional/nominal/pending-either metadata in their keys. Ordinary unannotated keys remain unchanged.

Pipeline currently converts SSign to Sign, then normalizes again and calls toDRS; this is a second evidence-loss seam. Proposed narrow backend lowering hook receives the selected sign plus its payload and calls occurrence-aware normalization/lowering. If the implementation instead uses existing rootFor reconstruction to recover payload, require a unique exact provenance+term match **with one identical origin map**; multiple different maps must abstain, never choose the first. The preferred explicit backend payload keeps the retained-reading identity visible. All selected and alternative readings need this path; fixing only srDRS leaves rrDRS inconsistent.

Add an internal `toDRSWithOrOrigins` variant that traverses the normalized term and consumes origins by the actual term path. It uses the same DRS lowering cases as toDRS, including the special forall/implication child paths; binder referents and claim statuses do not change. TAnd merges boxes only **after** each child has received its occurrence-local provenance. Keys consumed exactly once, and no unresolved paired obligation remains. An unconsumed key is a lowering failure, not permission to drop it. Ordinary leaf predicates retain the current lexical ProvIndex provenance.

Crucially, no new DRS constructor or exporter flag is required for the bounded no-duplication route. At a certified OR, set its COr provenance to `ProvRule CertifiedOrOccurrence [actualOrLeaf, pairedEitherLeaf?]`, with original source spans. Do **not** include operand provenance in this operator-specific tag: a nested operand's either must not mark the parent. Operand predicates/subboxes retain their own provenance; the full root derivation remains in the reading/explanation. A plain OR gets only its own OR leaf. Distinct source edge spans distinguish equal formulas in different clauses. A paired tag contains precisely the licensed marker, so the existing exporter obtains either=true for that OR only. Existing shared-fallback ambiguity logic remains intact for legacy uncertified nodes.

For initial annotated acceptance, require all OR nodes in that reading to have a trusted occurrence origin. Otherwise preserve the incomplete/residual distinction; do not let an uncertified OR reuse full-sentence either provenance and masquerade as another paired OR. This may reject some otherwise meaningful readings. Unsupported intensity/deindexing inside attitude Apps is a hard boundary for the first implementation: do not move paths through deindexWith without a reviewed rule. The prototype's quantifier transport checks paths only; production lowering must separately test universe scope and claims before approval.

## Independent controls and limits

`test/EitherOccurrenceProposalSpec.hs` is a standalone typed rewrite prototype using existing Term/typeOf/subst primitives. Cert uses small fixture edge/marker integers; these are **not** a real source-licensing implementation. It deliberately cannot prove lexical admission, parse coverage, Pipeline payload attachment or final DRS/claims. Those remain mandatory production integration tests, with the already independent operator gold unchanged. Four additional Boolean lowering callback controls exercise the real existing exporter: exact TF, exact TT, a plain outer OR with an inner marker, and rejection of an uncertified OR. This miniature callback is not the production DRT integration; it covers Boolean constructors only.

Controls fix TF/FT/TT on identical OR formulas in two conditional clauses; a plain outer disjunction containing one paired and one plain OR; direct beta identity and substitution into a consequent; negative duplicate/discard beta cases; equal-formula/different-evidence conjunction rejection; NOT and existential boundaries; capture avoidance; shadowing; forged predicate labels; erasure agreement; ordinary unmarked simplification. The TT case has separate physical source edges/markers. Repetition of a marker at the lexical level remains rejected by the pairing stage; beta reuse of an annotated argument remains deliberately rejected here.

For learner Unit2, a certificate records a selected licensed coordinator transition, not a category invention. Unit3 beta reduction transports the operator occurrence alongside the typed OR meaning. Unit4 COr receives only the edge's provenance; Asserted/Embedded partitions depend on DRS scope, not on either. In `Imp(Or(P,Q),Or(R,S))` the whole implication is Asserted and both ORs and their atoms Embedded. TF means antecedent marker only; it is not an XOR semantics switch. `Or(P,Q)` permits both, `Not(And(P,Q))` permits neither, and `And(Or(P,Q),Not(And(P,Q)))` is explicit XOR. No rule here supplies the missing NOT/AND conjunct or modal not-necessarily semantics.
