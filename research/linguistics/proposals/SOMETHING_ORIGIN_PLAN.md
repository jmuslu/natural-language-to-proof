# Something: lexical origin versus domain policy

Design only at accepted82efe8d. Four newly authored frozen190 controls are wrong
under their explicitly unrestricted entity-domain contract; the sealed outputs
are not evidence that existential force or negation scope is wrong. Do not repair
them by silently changing the default meaning or treating ordinary something as
a new unrestricted lexical noun.

## Separate decisions: meaning policy, lexical admission and construction

1. **Default domain:** preserve current ThingRestricted interpretation. The new
   controlled-entity-existential-v1 cases intentionally demand unrestricted x.
   An independently approved explicit domain policy could select
   `UnrestrictedEntity` for something, but this is not ContextUnknownNouns and
   must not be tied to nominal-copula policy, casing, benchmark name or gold IDs.
   It must affect every licensed something use coherently, not just four strings.
2. **Lexical origin:** retain actual offered exact NP and the closed pronoun
   branch. Do not allow N, NP[expl], NP[conj], arbitrary NP/N or N/N to mint the
   pronoun. A prospective N-origin path needs independent origin evidence and
   guard design; no N-only blockage is shown by these four cache rows.
3. **Relative construction:** current restrictedPronounEntries deliberately
   excludes something pending domain resolution. If licensed, reuse the existing
   paired quantified-pronoun NP+subject-relative certificate path; do not apply
   the ordinary noun+that reanalysis or offer a free NP/N head everywhere.

The Everyone implementation is a structural model: closed reservation/exact NP
term plus separately certified relative meaning and certificate validation.
Reuse that discipline and its type/provenance tests, not its universal force or
person restriction. Actual lexical occurrence belongs to the chosen alternative,
not all signs for a token. Distinct domain/origin decisions must survive packing
and explanations until the construction discharges. A new domain mode must be
recorded in producer protocol/replay before comparison; the current nominal-policy
protocol does not bind a hypothetical pronoun-domain option.

## Units2/3: candidate terms and transitions

Ordinary NP has Q=(e→t)→t. In ThingRestricted use
`S=λR.∃x(thing(x)∧R(x))`; in UnrestrictedEntity use
`S=λR.∃x.R(x)`. An adjectival VP `S[dcl]\NP` consumes Q. With
`λQ.Q(quiet)` it yields the positive row; with
`λQ.Q(λx.¬quiet(x))` it yields narrow negation under the same witness.
Domain selection never rewrites the VP or discards a negative operator.

For a certified subject relative, proposed internal head NP/N has
ThingRestricted `λP R.∃x(thing(x)∧P(x)∧R(x))` or unrestricted
`λP R.∃x(P(x)∧R(x))`. The matched relative source category
`(NP\NP)/(S[dcl]\NP)` becomes the certificate-bound N/VP meaning
`λV x.V(lift(x))`. Head/relative adjacency, actual source categories, exact source
identity and complete restriction consumption follow existing FusedCertificate
contracts. Add something to both lexical head selection and certificate validator
only after domain review; updating only one silently creates a mismatched API.
Reject orphan relatives, foreign source pairing, stale spans and object gaps;
no obligation may disappear through unary/coordination or packing.

For ordinary transitive object `Mira sees something`, source verb is
`(S[dcl]\NP)/NP`, meaning `λO S.S(λs.O(λo.see(s,o)))`.
ThingRestricted yields `[x|thing(x),see(Mira,x)]`; unrestricted yields
`[x|see(Mira,x)]`. Both assert the listed atoms; no name *Something* or shared
subject/object binder is introduced. This simple object case does not settle
inverse scope of two quantifiers or existential scope below a negated verb.

For `Something is red and quiet`, one witness must satisfy both predicates,
not two independent existential subjects. For a certified
`Something that is red is quiet`, intended ThingRestricted DRS is
`[x|thing(x),red(x),quiet(x)]`; under UnrestrictedEntity omit only thing.
All listed atoms are Asserted; no implication/relative property gets projected
outside a quantifier. With negative relative restriction, x still belongs to
the outer existential and only the relative property is nested in NOT; a separate
negative matrix VP keeps its own box. Reported or presupposed enclosing clauses
must preserve their boundaries and cannot create actual-world existential claims.

## Independent controls and limitations

`test/SomethingOriginProposalSpec.hs` tests current exact NP/reservation, five
unsupported categories and an actually offered N-only miniature dictionary.
It checks all four current ThingRestricted meanings, then independently checks
the incompatible controlled-domain expectations as intentionally red proposals.
Those paired checks deliberately cannot both pass under one unlabelled default.
Conjunction, ordinary object and three proposed subject-relative controls
(positive, negative restriction, negative matrix) also check
selected DRS, full Asserted/Embedded allocation and all returned canonical DRSs.
They use authored lexical offerings; none claims that these offerings were
observed in the real four cases. No population gold is changed.

The API for an explicit domain policy does not exist. Future tests must actually
select each policy, retain domain in certificate/packing identity, and reject
wrong policy metadata before scoring. Also add nested generic conditionals,
reported/presupposed content, origin guards for the specified relative scopes, object/subject two-
quantifier scope, wrong certificate source/branch, unsupported relative gaps,
and truth-equivalent-but-wrong canonical claims. Existing Everyone origin checks
are reusable patterns, not evidence these Something-specific paths are tested.

A conditional *if something is red then it is quiet* must retain antecedent-local
binding and consequent accessibility; no global top-level witness. Its legacy
controlled domain convention cannot be silently inferred from standalone source
semantics. A generic or negative-polarity environment does not license replacing
an existential with a universal or vice versa. Keep domain versioning separate
from scope/referent accessibility.

## Recommendation and source comparison

First document the domain conflict; do not activate a source fix based only on
four deliberately unrestricted authored cases. Static exact NP closed handling
already supplies existential force. A general lexical-origin repair needs an
actual category/origin counterexample; no such evidence was found in this sealed
observation subset. Prioritize a coherent reviewed domain contract if owner wants
these controls to define a new mode. Relative support is separately bounded and
must not be used to hide a standalone domain disagreement.

Boxer2008's construction/lexical-selection versus resolution separation supports
this distinction, as recorded in REFERENCES; it does not prove a unique thing
ontology for something. Pinned ccg2lambda2015 default NP uses existential force
and a two-slot restriction interface; Everyone uses _people. Neither authorizes
copying a universal person term into existential something or dropping an
independent domain predicate to improve a diagnostic score. Adopt explicit force
and scoped restriction, adapt the Q interface, and preserve independent gold.
No upstream parser or new corpus/LLM/model run was performed.
