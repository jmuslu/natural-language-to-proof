## Policy boundary comes first

The default execution must remain `either_constructions=legacy-disabled`, preserving existing lexical selection, normalization, packing, roots and export. The first optional route is `surface-inclusive-v1`: English either/or supplies inclusive OR plus an occurrence-local surface marker, never an automatic exclusive meaning. This is the default **English interpretation within the enabled route**, not a change to the current default execution. Neither a benchmark name nor expected gold may select a lexical meaning.

ProverQA controlled-exclusive gold is a separate contract. A precise either=true flag is not an explicit NOT(AND) condition and cannot make an inclusive DRS exact against XOR gold. The current solver's explicit `or_semantics=proverqa` maps markers to XOR; prohibit that consumer combination for an execution advertised as surface-inclusive-v1, or require a separately named, separately reviewed downstream convention. Do not silently reuse that convention in parser fidelity. Explicit *but not both*, modal *not necessarily both*, corrective *not P but Q*, and neither/nor remain unsupported paired extensions, not inputs to a domain guess.

Consequently an optional inclusive implementation can expose a new typed mismatch on an old exclusive-contract item previously no-parse. It must be reported as wrong under that original contract, not excluded or relabeled. No default landing or opt-in corpus trial is authorized by this plan. The first vertical acceptance panel is independently frozen, authored literal-English miniature fixtures; later root-approved old190/202 comparisons must preserve IDs/contracts and report any new wrong, which blocks expansion under the existing gate. An optional flag is not permission to hide regressions. Old default execution must remain exactly unchanged on every old case.

The protocol needs a separately reviewed versioned execution schema carrying `either_constructions` alongside existing parser/nominal policy. Current `nominal-policy-v1` has an exact-key validator in test/fidelity/fidelity.py; do not add an optional field silently or reinterpret old cache metadata. The exporter CLI must reject unknown combinations, echo the actual policy in success/error responses, and bind reports/replay to it. Hand parser must reject the enabled CCG-only option. Defaults, omitted flags, explicit disabled flags, invalid flags, and mismatched cached policies require wire tests before observations. Root owns protocol/cabal/schema integration; do not silently modify the accepted protocol in a lexical commit.
