# Optional either policy: integration result

The default remains unchanged. The coherent candidate adds an explicit
`surface-inclusive-v1` interpretation of directly paired either/or, with
occurrence-specific evidence carried from the chart to DRS lowering. It does
not infer benchmark exclusivity from the word either. The paired diagnostic is complete; default behavior remains unchanged.

## What is implemented

For STUDY_PLAN Unit 2, the chart requires an actually offered compatible `X/X`
category for either, an explicit lexical or coordinator, exact feature/category
agreement, and contiguous source-token operands. It reserves unsupported either
forms in the enabled policy. Pending markers cannot escape through composition,
unary conversion, punctuation or a partial root. One terminal period cannot
become an internal operand or be repeatedly attached.

For Unit 3, the pending identity term is a capability awaiting a specific
coordination derivation, not a freely usable identity rule. The existing VP type
is `GQ → t`, where `GQ = (e → t) → t`: subject quantifiers stay outside the coordinated
predicates, sharing one subject witness. The shared coordination constructor
provides exact occurrence paths; normalization carries those paths through the
actual term transformations. Missing, duplicated, stale or unaccounted-for
origins fail explicitly instead of being rediscovered from a formula or a global
surface-word search.

For Unit 4, each active candidate keeps its own ordered score, notes and evidence.
Lowering consumes every OR origin exactly once and attaches only its operator
leaves to that COr. Embedded atoms remain Embedded; negation and quantifier scope
remain intact. A typed origin failure retains the typed form and reading index
but supplies no DRS. The exporter and Explain report the origin failure honestly.
The historical aggregate scorer label `type_failure` for typed readings lacking
a DRS is unchanged; it is not proof that the term failed type checking.

The [operator lesson](sections/design-operators.md) and reviewed
[interface plan](proposals/either-carrier-plan.md) explain the Boxer/ccg2lambda
comparison. The implementation adapts compositional Boolean semantics while
keeping this project's explicit source-origin and claim-status requirements.
It does not import automatic XOR or erase benchmark/English contract differences.

## Optional result and limits

Exactly four complete responses change relative to explicit disabled; the other
204 are identical after removing only top-level execution metadata. Nathalia is
either cautious or timid, Mira is either quiet or tall, and Noel is either young
or red each move from no parse to a sole exact inclusive-OR reading. Each has one
Asserted OR and Embedded atoms. There are no new wrong results under any frozen
contract, no exact regressions, no trace-only changes, and no origin failures.

The fuller sentence “Every bird either knows the troposphere or reveres Joziah
(or both)” moves from a wrong reading to no parse. This removes the output-level
spurious either/both predicates by abstaining; it does not recover the intended
universal meaning. This is an abstention improvement, not an exact gain. These
output comparisons do not establish the earliest failing chart step; Explain
replay improvements remain deferred.

Nathalia and Mira retain the existing unknown-capitalized-name heuristic in
their traces. These results do not certify general name recognition or identity
isolation. The corpus exporter exposes marker flags and traces, not the complete
COr provenance tree: exact operator-origin checks are supported separately by
source review and independent synthetic integration controls. Explicit XOR,
sentence-level either, and unsupported nested/parenthesized constructions are
not established by these three positive examples.

Enabled evidence is sealed in `research/runs/either-policy-surface-inclusive-v1`.
The policy is an explicit bounded capability, not a new default or permission to
resume answer benchmarks. No gold, strict scorer or contract was relabeled.
